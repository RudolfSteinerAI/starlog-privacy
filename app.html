Privacy policy GitHub

On the device

  • Log text, tags, classification, stardate, officer or vessel name, audio, and video stay in the app’s private storage.
  • There is no STARLOG account and no STARLOG server for logs.
  • STARLOG does not sell data, show ads, or upload log entries.
  • Android backup and device-to-device transfer of app data are turned off.

PIN

On the Android app, an optional PIN encrypts the archive at rest (AES-256-GCM). Argon2id wraps a data key, and Android Keystore holds key material. A wrong PIN fails the authentication tag. STARLOG cannot recover a forgotten PIN. With no PIN, logs stay on the device as plaintext. Clearing the PIN requires the current PIN and a warning that the archive will be stored as plaintext again.

In the browser, an optional PIN encrypts that web archive at rest (WebCrypto PBKDF2 and AES-GCM). It is secure only when a vault exists. A legacy hash-only lock stays locked, with plaintext entries, until you migrate. Clearing the PIN requires the current PIN and returns the archive to plaintext. There is no STARLOG server.

Optional biometric unlock on the Android app is available only after a PIN is set. STARLOG does not receive face or fingerprint templates. The device Keystore and Class 3 biometrics handle that unlock on the device. The web archive does not offer biometric unlock.

An older hash-only lock on the Android app stays closed, and the archive stays plaintext, until the first successful unlock moves it into the encrypted vault. That lock is secure only when the vault is present.

Dictate

Dictate is optional. STARLOG uses speech only when the device reports that on-device speech is available. It does not silently fall back to a cloud speech-to-text service, and it does not send that audio to a STARLOG server.

A phone maker’s own speech service may still handle the audio. STARLOG does not control that service, and does not promise that vendor speech never leaves the phone.
