STARLOG privacy policy

Package com.starlog.app · Personal log stored on the device

STARLOG is a personal log. Entries stay on the device. There is no STARLOG account and no STARLOG server for logs.

What stays on the device

Log text, tags, classification, stardate, officer and vessel name, audio, and video are stored in the app's private storage. With no PIN they are plaintext. When a PIN is set they are encrypted at rest. Android backup and device-to-device transfer of this app's data are disabled.

Speech

Begin Log with Transcribe on appends words to the text field. That control asks for on-device speech recognition. STARLOG starts that only when the device reports an on-device engine (Android 12 or later). If it does not, the app says speech is unavailable and does not listen. A denied session says speech is denied. Too many requests says throttled. STARLOG does not switch to a cloud recognizer and does not retry with on-device recognition turned off.

That engine belongs to the device maker or Google. Android's on-device speech API is documented not to use the network. STARLOG does not run that engine and does not receive a copy of anything it might send. This is not a promise that speech never leaves the phone.

Network

The release app does not request the Internet permission, and it does not call a STARLOG server. Debug builds may still allow the Flutter tool to attach. A speech service, if one were started, would run in another app. STARLOG does not start recognition unless the device reports an on-device engine.

Permissions

  • Microphone — only when the user taps Begin log, Record Audio, or Record Video.
  • Camera — only when the user taps Begin log with video selected, or Record Video.
  • Speech recognition — only when the user begins a log with Transcribe on, and only if an on-device engine is available.
  • Biometric — only if the user arms sensor unlock after a PIN, and then taps Use biometric. The template stays on the device. STARLOG does not receive it.

Export and share

JSON copy, share, and the system share sheet run only when the user taps them. The file is a versioned text backup: entry fields, officer and vessel, and any transcript the user saved. Audio and video files are not included.

SHARE AUDIO or SHARE VIDEO on one log sends that recording through the system share sheet, and only when the user taps it. Archive EXPORT offers those same controls when the log has a recording. After that share finishes, REMOVE FROM PADD can delete the recording from this device. It asks first. Cancel and a failed share leave the file. The log is not uploaded to a STARLOG server.

Lock

The PIN is optional. With no PIN, logs stay in plaintext on this device. When a PIN is set, logs, settings, and media are encrypted at rest. STARLOG cannot recover a forgotten PIN. Clearing the PIN requires the current PIN and stores the archive as plaintext again. An optional sensor unlock can be armed only after a PIN. It uses this device's biometric to unwrap the same data key. STARLOG does not receive a face or fingerprint template. If the sensor is unavailable, denied, or fails, the PIN keypad remains. The sensor cannot clear the PIN.

What STARLOG does not do

We do not sell data. We do not run ads. We do not upload logs to a STARLOG server.
