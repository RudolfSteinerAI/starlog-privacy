STARLOG privacy policy

Package com.starlog.app · Updated 22 September 2026

STARLOG is a personal log. The Android app keeps entries on the device. The web archive stays in the browser you use. This page says what the app stores, and what it does with the microphone, camera, speech, export, PIN, and biometric unlock. It also says how an optional PIN treats the web archive.

Entries stay on the device

Log text, tags, classification, stardate, officer or vessel name, audio, and video are stored in the app’s private storage on the device. There is no STARLOG account. There is no STARLOG server for logs. The web archive stays in the browser you use. STARLOG does not upload it.

STARLOG does not sell data and does not show ads. It does not upload your log entries. Android backup and device-to-device transfer of app data are turned off.

Microphone and camera

  • Microphone — used only when you tap Record Audio, Record Video, or Dictate.
  • Camera — used only when you tap Record Video.

Audio and video you record stay on the device with the log.

Speech

Dictate is optional. STARLOG uses speech only when the device reports that on-device speech is available. The app does not silently fall back to a cloud speech-to-text service.

STARLOG does not send that audio to a STARLOG server. A phone maker’s own speech service may still handle the audio. STARLOG does not control that service, and does not promise that vendor speech never leaves the phone.

Export

A JSON copy, a file export, or the system share sheet runs only when you tap it. The JSON export is text and metadata only. Audio and video stay on the device and are not included in the JSON file.

PIN

You can set an optional PIN. STARLOG cannot recover a forgotten PIN.

Android app. When a PIN is set, the log archive is encrypted at rest with AES-256-GCM. Argon2id wraps a data key, and Android Keystore holds key material on the device. A wrong PIN fails the authentication tag, so the archive does not open. If you do not set a PIN, log entries stay on the device as plaintext. Clearing a PIN requires the current PIN. STARLOG warns you that clearing it writes the archive back as plaintext on the device.

An older Android install that stored only a hash of the PIN was not encrypted. That lock stays closed, and the archive stays plaintext, until the first successful unlock moves it into the encrypted vault. STARLOG treats the lock as secure only when that vault is present.

Web archive. An optional PIN encrypts the archive at rest in that browser. WebCrypto derives a key with PBKDF2 and encrypts with AES-GCM. There is no STARLOG server for that archive. STARLOG treats it as secure only when a vault exists. A legacy hash-only lock stays locked, and the entries stay plaintext, until you migrate them into the vault. Clearing the PIN requires the current PIN and writes the archive back as plaintext in that browser.

Biometric unlock

Biometric unlock is optional on the Android app, and only after a PIN is set. It is not available for the web archive. Face or fingerprint can then unlock the app on this device. STARLOG does not receive face or fingerprint templates. Unlock uses the device Keystore and Class 3 biometrics only. STARLOG does not upload biometric data.

The PIN still encrypts the archive at rest when it is set. Biometric unlock does not replace that PIN. Clearing the PIN still requires the current PIN, and STARLOG still warns you that the archive will be stored as plaintext.
